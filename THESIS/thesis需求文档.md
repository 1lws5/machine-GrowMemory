# 传送带分拣控制系统 — 需求文档

## 系统概述
传送带运送物体经过颜色传感器，识别颜色后用气缸推杆推到对应轨道。

## 工作流程
1. 按下启动按钮 → 传送带运行
2. 物体到达检测位 → 到位传感器=TRUE
3. 颜色传感器读取颜色代码（1=红/2=蓝/3=绿/0=未识别）
4. 对应推杆动作 → 伸出2秒 + 回位1秒
5. 传送带继续运行，等待下一个物体
6. 按下停止按钮 → 传送带停止

## I/O 点表
| 变量名 | 类型 | 地址 | 方向 | 说明 |
|--------|------|------|------|------|
| iStart | BOOL | %IX0.0 | 输入 | 启动按钮（常开） |
| iStop | BOOL | %IX0.1 | 输入 | 停止按钮（常闭，真实接线时取反） |
| iDetect | BOOL | %IX0.2 | 输入 | 到位检测传感器 |
| iColorCode | INT | %IW2 | 输入 | 颜色传感器代码（1=红/2=蓝/3=绿/0=未识别→报警） |
| qBelt | BOOL | %QX0.0 | 输出 | 传送带电机 |
| qPushA | BOOL | %QX0.1 | 输出 | 推杆A（红色） |
| qPushB | BOOL | %QX0.2 | 输出 | 推杆B（蓝色） |
| qPushC | BOOL | %QX0.3 | 输出 | 推杆C（绿色） |
| qRunLight | BOOL | %QX0.4 | 输出 | 运行指示灯 |
| qAlarmLight | BOOL | %QX0.5 | 输出 | 报警指示灯 |

内部变量（无物理地址绑定，仿真靠监视窗口强制）：
| 变量名 | 类型 | 说明 |
|--------|------|------|
| bAlarmReset | BOOL | 报警复位按钮（上升沿触发） |
| bCntReset | BOOL | 计数复位按钮（上升沿触发） |
| wCountRed | INT | 红色计数 |
| wCountBlue | INT | 蓝色计数 |
| wCountGreen | INT | 绿色计数 |
| wCountTotal | INT | 总计数 |

> 地址说明：%IX0.0~0.7 = 字节0，%IX1.0~1.7 = 字节1。
> %IW0 = 字节0+1，会与 %IX0.x 冲突，故颜色代码用 %IW2（字节2+3）。

## PLC 程序结构
- PLC_PRG（主程序）：启保停+颜色检测+推杆控制+安全保护+HMI数据
- FB_BeltControl（传送带控制DFB）
- FB_Pusher（推杆控制DFB，实例化3个）
- FB_Sorter（分拣逻辑DFB）
- GVL（全局变量表，I/O绑定）

## HMI 界面
- 主界面：启动/停止按钮、运行指示灯、传送带动画
- 分拣监控：红/蓝/绿计数、当前颜色代码、推杆状态
- 报警页面：未识别报警、急停状态

## Modbus TCP 通信
- **主站（Client）**：上位机 / HMI（主动发起读，查询 PLC 数据）
- **主站（Client）**：上位机 / Python 脚本（主动发起读，查询 PLC 数据）
- **从站（Server）**：Codesys PLC（被动响应，把计数数据挂到输入寄存器）
- **协议**：Modbus TCP，端口 502
- **从站设备**：ModbusTCP Server Device（通用 TCP 服务器，无 Unit ID）
- **寄存器映射（Input Register，功能码 04 读）**：

| Modbus 地址 | 偏移 | 映射变量 | 类型 | 含义 |
|------------|------|----------|------|------|
| 30001 | 0 | GVL.mbCountTotal | INT | 分拣总数 |
| 30002 | 1 | GVL.mbCountRed | INT | 红色计数 |
| 30003 | 2 | GVL.mbCountBlue | INT | 蓝色计数 |
| 30004 | 3 | GVL.mbCountGreen | INT | 绿色计数 |

> 说明：
> - Input Register 为 16 位字，每个 INT 变量占 1 个寄存器。
> - 计数是 PLC 输出给上位机读，应放 **Input Register（%QW）**，主站用 **功能码 04**。
> - GVL 用 `AT %QW` 声明映射变量（如 `mbCountTotal AT %QW0 : INT`），避免 I/O 映射与程序赋值冲突。
> - GVL 开了 qualified_only，映射和程序中变量需带 `GVL.` 前缀。
> - 运行状态寄存器已砍掉；若需运行状态，可后续新增 `wRunState` 并映射到 %QW4。

# 进阶版（实际项目需要，学习版已简化）

> 本章说明：以下内容为**真实工业分拣系统必须具备、但本学习项目为降低复杂度而简化的设计**。
> 记录在此以体现对真实项目复杂度的认知。

## 1. 物体跟踪（编码器 + 移位寄存器）
**简化版问题**：检测点与推杆位置重合，识别完立刻推。真实系统中，颜色传感器与各推杆站沿传送带**分开分布**，识别完物体还要继续走一段才到对应推杆。

**真实做法**：
- 编码器装在传送带滚轴上，传送带每前进一个固定距离发出 1 个脉冲，PLC 靠数脉冲判断物体走了多远。
- 移位寄存器（数组队列）把传送带划分成若干"格"，数组每个元素 = 传送带上的 1 格，用队列移动模拟物体前进。
- 预先记录 A/B/C 三根推杆各自对应的格号（数组索引）。
- 检测点识别到颜色 → 塞进队列头部；每来 1 个脉冲 → 队列右移 1 格；颜色数据移位到某推杆格号 → 触发该推杆并清空该格。

## 2. 卡料超时保护
**简化版问题**：工件触发到位传感器后，无超时检测。

**真实做法**：到位传感器触发后启动超时定时器，若长时间收不到分拣完成信号（bSortDone），判定卡料故障，报卡料报警并停机，防止设备在故障状态下空转。

## 3. 推杆位置反馈（双传感器）
**简化版问题**：推杆动作靠纯延时（伸出2秒/回位1秒），无法确认推杆真实到位。

**真实做法**：每个气缸装两个位置传感器——"推到底"传感器和"归位"传感器。推到底→推杆传感器变TRUE，保持一会儿后开始收回；收回到位→归位传感器变TRUE，才允许下一次推杆。避免延时猜测导致的机械误差。

## 4. 报警锁存 + 复位确认
**简化版问题**：报警后设备锁停，但复位逻辑简单。

**真实做法**：报警状态必须锁存（置位后保持），复位用上升沿检测（R_TRIG），长按复位按钮不会重复触发。报警未处理完成时不允许直接清除，需人工确认故障排除后才复位解锁。

## 5. 停止按钮接线（常闭 vs 常开）
**简化版问题**：仿真阶段 iStop 当常开用（按下=TRUE）。

**真实做法**：急停/停止按钮按安全规范接**常闭触点**，接线断开时 PLC 读到 FALSE，代码需取反判断（IF NOT iStop）。这样按钮断线时设备自动停机，实现"故障安全"（Fail-Safe）。

## 6. 计数复位接口
**简化版问题**：计数变量无外部清零接口，热下载/在线修改不清零。

**真实做法**：提供计数复位输入引脚，HMI 一键清零统计计数。

## 7. 防重复触发
**简化版已实现**：传感器持续高电平不重复触发分拣（NOT bSorting 锁存防护）。

**真实做法**：到位传感器加去抖/滤波，配合锁存标记，防止抖动和多次触发。

## 8. 颜色传感器信号滤波
**简化版问题**：假设到位瞬间颜色值已稳定。

**真实做法**：颜色传感器输出需去抖滤波，避免在扫描周期内跳变导致颜色判断错误；必要时在检测点加"物体在位"稳定信号后才读取颜色值。

## 9. 颜色判定位置与信号采集方式
**简化版问题**：代码直接读 `iColorCode`（INT 1/2/3），没有颜色判定代码，隐含假设"传感器已把颜色变成数字"。

**真实做法**：颜色判定不在 PLC 里，而在传感器内部——真实颜色传感器（基恩士/SICK/欧姆龙）通过"示教"（Teach）存下三种颜色的光谱指纹，物体经过时自行比对输出分类结果。PLC 只负责读结果。按采集方式分三种：
- **开关量**：3 路 BOOL（OUT1=红/OUT2=蓝/OUT3=绿），PLC 端需写编码逻辑（IF iColorRed THEN iColorCode:=1 ...）。
- **数字接口（IO-Link）**：直接输出数字 1/2/3，PLC 直读 INT，无需判定代码（本项目采用）。
- **模拟量**：RGB 三路 0-10V/4-20mA，PLC 端需采样+阈值判断，才是真正的"颜色算法"。

> 说明：颜色代码来自传感器示教后经 IO-Link 直读数字；若用开关量传感器，PLC 端需补一段编码逻辑。

## 10. 分拣方式：暂停 vs 连续（on-the-fly）
**简化版问题**：采用"暂停分拣"——识别到物体后暂停传送带，等推杆动作完成（伸出2秒+回位1秒）再恢复。一次只处理一件，串行阻塞，吞吐量极低。

**真实做法**：传送带不停，连续运行，边跑边推（on-the-fly 在线分拣）。三个推杆沿传送带空间错开排列（A/B/C 三站），物体走到各自杆站的时间天然不同：
- 三杆独立并发，互不等待——红物体在 A 站被推时，蓝物体还在传送带上继续走。
- 两个物体同时分别到达 A 站和 C 站，A 杆和 C 杆可同时推，互不干扰。
- 吞吐量 = 传送带速度 × 物体间距，而非"1个/(识别+推+回时间)"。

> 核心因果：连续运行下"现在该推谁"不再是显然的，多个物体同时在传送带上移动，PLC 必须记住"每个物体是什么颜色、走到哪了"，这正是需要"物体跟踪"（见第1条）的根本原因。暂停→无需跟踪（一次一件）；连续→必须跟踪（多物体并发）。
