## 1. 项目结构（5个文件）

| 文件 | 类型 | 作用 |
|------|------|------|
| GVL | 全局变量表 | I/O地址绑定 + 计数/复位等内部变量 |
| FB_Pusher | 功能块 | 推杆控制（伸出2秒→回位1秒） |
| FB_BeltControl | 功能块 | 传送带启保停 + 暂停 + 运行灯 |
| FB_Sorter | 功能块 | 颜色识别 + CASE分拣 + 计数 + 报警 |
| PLC_PRG | 主程序 | 调用上述功能块，串联数据流 |

## 2. 完整调试流程（记忆口诀）

```
F11编译 → 启动仿真器 → Alt+F8登录 → 下载"是" → F5运行 → 监视变量强制
```

### 2.1 编译

| 操作 | 按键/菜单 | 说明 |
|------|----------|------|
| 生成代码 | F11 | 编译整个项目，比F7更彻底 |
| 看结果 | 消息窗口 | 0 error = 通过；有 C0xxx 错误双击跳转 |

### 2.2 启动仿真器

- 开始菜单 → CODESYS Control Win SysTray
- 系统托盘出现 C64 图标 = 仿真器已启动
- 没图标就先启动，否则登录时扫不到设备

### 2.3 登录（Login）

快捷键 `Alt+F8`。可能遇到的弹窗：

| 弹窗 | 处理 |
|------|------|
| 活动路径选择设备 | 选 CODESYS Control Win V3 x64，点确定 |
| 扫描本机设备 | 点"是(Y)" |
| 通信IP输入 | 输入 localhost 回车 |
| 设备用户密码 | 见第6章"密码问题" |

### 2.4 下载（Download）

登录后提示"程序与设备不一致，是否下载" → 点"是"。或菜单：在线 → 下载。

### 2.5 运行（Run）

按 `F5`，程序开始在仿真器里循环执行。

### 2.6 监视 / 强制变量

1. 双击打开 PLC_PRG 或 GVL
2. 菜单 在线 → 写入值 / 强制值
3. 找到变量，双击"准备值"列输入值
4. 按 `Ctrl+F7` 写入（写一次）或 `Ctrl+F8` 强制（持续锁住）

## 3. 模拟测试顺序（关键！）

> **颜色分拣必须【先设颜色，再触发到位】，顺序不能反。**

| 步骤 | 操作 | 预期结果 |
|------|------|----------|

| 6 | 观察 GVL.wCountRed | 计数变1 |
| 7 | 强制 GVL.iStop := TRUE | 整机停止 |

## 4. 颜色代码 0 的时序（易混淆点）

`iColorCode=0` 在代码里是"未识别→报警"。但初始状态不会误报警，因为报警代码在 CASE 的 ELSE 分支，而整个 CASE 被这个条件包住：

```iecst
IF rTrigDetect.Q AND bRunning AND NOT bSorting THEN
    CASE iColorCode OF
        1: ...
        2: ...
        3: ...
        ELSE
            qAlarmLight := TRUE;  -- 报警
    END_CASE;
END_IF;
```

触发条件是 `iDetect` 的上升沿。初始 `iDetect=FALSE`，没有上升沿，进不了 IF，所以 `iColorCode=0` 不会误报警。

只有"物体到位那一拍"才读 iColorCode，那时读到 0 才报警——正是"有物体但颜色没识别"的正确含义。

| 场景 | 操作 | 结果 |
|------|------|------|
| 正常分拣 | 先设颜色1/2/3，再触发iDetect | 对应推杆动作 |
| 测报警 | 故意设0，再触发iDetect | 报警灯亮，传送带锁停 |
| 解除报警 | GVL.bAlarmReset := TRUE | 报警清除，恢复运行 |

## 5. 一键重置（清掉上次状态）

仿真器进程一直跑着，上次的变量值和强制值都残留。重置三步：

1. 解除所有强制：在线 → 强制值 → 解除所有强制
2. 冷复位：在线 → 复位 → 冷复位(Cold Reset)，清空所有变量
3. 重新下载 + F5运行

更彻底的办法：托盘 C64 图标右键 → 退出，彻底关掉仿真器进程，再重启 → 登录 → 下载。

```
记忆口诀：解除强制 → 冷复位 → 重新下载 → F5运行
```

## 6. 密码问题（忘了密码）

密码存在工程文件里（加密），翻不到明文。正确做法是在 IDE 里重置：

### 6.1 关掉设备用户认证（最快）

在线 → 安全 → 设备用户管理 → 选 CODESYS Control Win V3 x64 → 删除/禁用用户 或 勾掉"启用用户管理"。

### 6.2 在工程里重置用户

左侧设备树 → 双击 Device → "用户和组"标签 → 选中用户删除或改密码 → 重新下载。

## 7. 常见警告（可忽略）

| 警告 | 原因 | 处理 |
|------|------|------|
| 地址未使用 | 仿真器无真实I/O硬件，AT %IX0.0 等地址无效 | 忽略，接真机时才生效 |
| C0139 无效果 | 定时器ET等输出未使用 | 忽略，不影响运行 |

## 8. 调试要点备忘

### 8.1 扫描周期顺序（进阶）

PLC_PRG 从上往下执行。fbBelt 和 fbSort 互相依赖，暂停信号天然滞后一拍（约10ms），传送带场景可忽略，不必过度优化。

### 8.2 推杆 bDone

FB_Pusher 触发动作时立刻 `bDone:=FALSE`，回位完成才 `bDone:=TRUE`，保证外部读到的是准确的"完成"信号。

### 8.3 复位信号

报警复位、计数复位都做了 R_TRIG 上升沿检测，长按按钮不会重复触发。
